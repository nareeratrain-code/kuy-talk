# Kuy Talk – แชทหาคู่ + สุ่มคุย + ห้องแชท 77 จังหวัด (ต้นแบบ)
Run: `npm install && node server.js` → http://localhost:3000 (`PORT` env). Data: `data.json` (delete to reset → bots only).
Admin: http://localhost:3000/admin (HTTP Basic auth, any username, password = `ADMIN_PASSWORD` in `.env`, chmod 600, git-ignored).
Tests: `node test.js` (API + sockets, 32 checks). Browser smoke: `npm i puppeteer-core && node smoke.js` (uses /usr/bin/google-chrome).

## Pages
- `/` – the user's original Kuy Talk UI (`public/index.html`) + `public/kuy-bridge.js` wiring it to the backend.
- `/classic.html` – mobile swipe-deck UI, same account (localStorage `kt_token`).
- Both use `public/kt-call.js` (WebRTC 1:1 voice/video, Socket.IO signaling, STUN only).

## Backend (server.js, Express + Socket.IO + JSON store)
Accounts (18+), swipe/like (100 free/day, persisted), match → DM (realtime, typing), random chat (humans, bot fallback, paid gender filter),
77 province rooms (`provinces.js`: join/leave, live counts, last 100 msgs saved, typing, flood limits, swear filter, `<>` stripped server-side, bots in popular rooms),
moments (text/photo, like, comment), friends (request/accept from matches; bots auto-accept), lucky spin (1 free/day) & shake → real match,
block (hidden everywhere, DMs/calls/random refused) & report (stored, admin review), admin ban/unban, Premium 30 days enforced server-side.
Payments are SIMULATED (top-ups, ฿50 Premium); no card data is collected.

## Limitations
JSON file store (single process); token-only auth (no password/OTP); calls need a TURN server for many real networks; age is self-declared; swear list is small.
Backups: `backup-v1/` (first version + user's original file), `backup-v2/` (before this update).

## Deploy to Render
1. Push this repo to GitHub, then on Render: **New → Blueprint** → pick the repo (uses `render.yaml`), or New → Web Service with build `npm install`, start `npm start`.
2. Set env var `ADMIN_PASSWORD` (Render asks because `sync:false`). Without it, `/admin` is disabled. Render sets `PORT` automatically.
3. ⚠️ Free plan disk is ephemeral and the service sleeps after ~15 min idle: `data.json` (accounts, chats, rooms) is wiped on every redeploy/restart. For persistence use a paid plan with a disk (uncomment `disk` + `DATA_DIR=/var/data` in render.yaml) or move to a database.
4. WebSockets work on Render out of the box. Calls may still need a TURN server.

## GPS, Postgres, phone OTP, PDPA (v2026-10-23)

**Location** – browser geolocation after a Thai explanation sheet + separate PDPA consent. Coordinates are fuzzed (~100–300 m: 0.0025° grid snap + stable per-user offset) before storage and are never returned by any API; other users only see `distLabel` (`< 1 km`, `1.2 km`, `ในอำเภอ X`, `ในเขต X`, `จ.X`, `ซ่อนระยะทาง`). Offline reverse geocoding: `geo/th-districts.json` (928 amphoe centroids, GeoNames CC-BY + thailand-geography-data). Ranking = Turbo then haversine distance; candidate lookup uses a 0.25° in-memory grid and, on Postgres, an indexed lat/lng bounding-box query. Filter steps 1/5/10/25/50/100 km/ทั้งประเทศ. Denied/paused → province centroid. Settings: pause, hide distance, delete location, withdraw consent.

**Storage** – `DATABASE_URL` set → Postgres (`kt_users` rows with lat/lng index + `kt_kv`), only changed rows are flushed (debounced, transactional). Unset → `DATA_DIR/data.json` (local dev). Render free web disks are ephemeral, so production **needs** DATABASE_URL.

**Phone OTP** – `/api/otp/request` + `/api/otp/verify`: Thai mobile (+66/0, 6/8/9 prefix), 6-digit code (HMAC-hashed), 5 min expiry, 60 s resend cooldown, 5 sends/hour/phone, 10/hour/IP, 5 wrong tries, 30 verifies/10 min/IP. Sessions = random 32-byte tokens stored hashed, in an HttpOnly `kt_s` cookie (180 days) + `x-token` header. Logged-in users can link a phone. With no SMS provider configured the code is shown on screen labelled **โหมดทดสอบ**.

| Env var | Purpose |
|---|---|
| `DATABASE_URL` | Postgres connection string (`?sslmode=require` for Neon) |
| `SMS_PROVIDER` | `thaibulksms`, `twilio` or `console` (default) |
| `THAIBULKSMS_API_KEY`, `THAIBULKSMS_API_SECRET`, `THAIBULKSMS_SENDER` | ThaiBulkSMS API v2 (sender name must be approved) |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM` / `TWILIO_MESSAGING_SERVICE_SID` | Twilio |
| `OTP_SECRET` | HMAC key for OTP hashes (auto-generated in render.yaml) |
| `OTP_COOLDOWN_MS`, `SIGNUP_PER_MIN` | test overrides only |

**Legal / PDPA** – Thai drafts in `public/legal/*.html` (generated by `node scripts/gen-legal.js`): terms, privacy (PDPA), cookies, community standards, payments/refunds, dating safety, deletion & data requests. Replace `[ชื่อบริษัท]`, `[ที่อยู่]`, `[อีเมล DPO]` etc. and **have a Thai lawyer review before launch**. Signup requires 18+/terms/privacy checkboxes; location and marketing consents are separate and logged (`db.consents`, with version, time, IP, UA). Users can export their data (JSON), file data-subject requests (30-day due date), contact support (admin panel shows tickets + requests), withdraw consents, log out everywhere and delete their account. Traffic log (signup/login/OTP events) kept 91 days (Computer Crime Act s.26).

Tests: `OTP_COOLDOWN_MS=3000 SIGNUP_PER_MIN=100 node server.js` then `node test.js` (also run with `DATABASE_URL=...`).
